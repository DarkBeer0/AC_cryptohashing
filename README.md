# Record Hashing

Учебная задача на обработку больших объёмов данных.

## Условие

Есть таблица `records` с большим количеством записей (десятки миллионов).
Для каждой записи необходимо выполнить ресурсоёмкую криптографическую операцию —
вычислить несколько раундов SHA-256 от исходных данных — и сохранить результат
в таблицу `record_hashes`. Перед вычислением хэша все поля записи из таблицы
`records` необходимо сконкатенировать.

## Среда

- PostgreSQL 17 в Docker (`docker-compose.yml`)
- схема БД — `db/init/001_schema.sql` (применяется автоматически при первом старте)
- Node.js + TypeScript, драйвер `pg`

| Команда             | Что делает                                              |
| ------------------- | ------------------------------------------------------- |
| `npm run db:up`     | поднять PostgreSQL и дождаться готовности               |
| `npm run seed`      | наполнить `records` (`SEED_ROWS` строк из `.env`)        |
| `npm run status`    | сколько записей всего и сколько хэшей посчитано         |
| `npm start`         | посчитать хэши (`src/index.ts`)                         |
| `npm run db:psql`   | открыть psql внутри контейнера                          |
| `npm run db:reset`  | удалить том с данными и создать БД заново               |
| `npm run db:down`   | остановить PostgreSQL (данные сохраняются)              |
| `npm run typecheck` | проверка типов                                          |

## Первый запуск

```bash
cp .env.example .env
npm install
npm run db:up
npm run seed
npm run status
```

Начинать лучше с `SEED_ROWS=1000000` (секунды на генерацию, ~180 МБ на диске),
а когда решение заработает — увеличить до 10–50 млн и посмотреть, как оно себя ведёт.
`npm run seed` можно запускать повторно: он досыпает строки до `SEED_ROWS`.

## Параметры (`.env`)

- `SEED_ROWS` — сколько строк должно быть в `records`
- `HASH_ROUNDS` — сколько раундов SHA-256 считать для одной записи
- `DATABASE_URL` — строка подключения

## Замеры

Условия: 1 000 000 записей в `records`, `HASH_ROUNDS=1000`, `BATCH_SIZE=1000`,
машина с 24 логическими ядрами. Скорость — среднее за первые 7 000 записей.

| Версия       | Потоков | Скорость, записей/с | Время на пачку | Доля хеширования | 1 млн записей | 10 млн записей |
| ------------ | ------- | ------------------- | -------------- | ---------------- | ------------- | -------------- |
| Однопоточная | 1       | ~670                | ~1,49 с        | ~99,4%           | ~25 мин       | ~4,1 ч         |

Почти всё время уходит на вычисление SHA-256, работа с базой занимает меньше 1%.
Узкое место — процессор, поэтому распараллеливание хеширования по ядрам
должно дать почти линейный прирост.
